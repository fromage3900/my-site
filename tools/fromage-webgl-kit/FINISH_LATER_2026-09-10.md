# Shared evidence standard

Every claim used in an application must map to one of:

```text
LIVE URL
LOCAL RUNTIME CAPTURE
SOURCE FILE
MEASURED DIAGNOSTIC
DCC SOURCE / EXPORT
DOCUMENTED OWNER EXPERIENCE
```

Never promote a source-intended feature into a runtime claim before it has been observed.

Use these status words consistently:

- `SOURCE-SEEDED` — code exists but is incomplete or only a starting point;
- `SOURCE IMPLEMENTED` — intended feature is present in source;
- `RUNTIME VERIFIED` — observed in a real execution environment;
- `CAPTURED` — evidence still/image/video exists;
- `PROPOSAL READY` — listing is current, must-haves are truthful, and relevant evidence exists;
- `PAID` — money actually received.

---

# Proposal gate

A strike can become `PROPOSAL READY` only when:

1. the listing is still active/current;
2. relevant runtime evidence exists;
3. every must-have we claim can be demonstrated or honestly described as prior owner experience;
4. missing requirements are disclosed rather than implied;
5. no client-specific unpaid deliverable was produced;
6. the economics still justify the human time;
7. proposal submission remains a human decision.
